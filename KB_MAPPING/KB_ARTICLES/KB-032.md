## Content requirements

Concepts:
- The phone map is the same 2017 map, not a separate mobile map page.
- Opening mobile home clears an in-progress process.
- There is no footer Transfer. Transfer is in the menu when products exist.
- A return token of Map without .aspx lands on mobile home, not the map.

Prerequisites and permissions:
- Signed in. About 900px wide uses the phone layout.

Customer actions:
1. Open the menu: Home, Map, Products, Activity, Check In, Check Out, Transfer, Quick Scan, Help, Settings, Logout.
2. Pick a location. Use the default badge to change the saved default.
3. Finish the movement.
4. On the map, use the bottom bar: Edit, Clone, Vertical, 3D, Delete, Close. The first tap selects.

Options and settings: Tablet mode turns multi-select off. Pinch-zoom of the browser page is disabled so the map can zoom.

Expected results: The live mobile save uses the Transfer backend when the old product list cookie is empty.

Errors and troubleshooting: Empty recent locations: “No recent locations.” Success banners: “Check-in completed successfully.” and the check-out and transfer equivalents.

Limitations:
- Do not document Mobile/Map.aspx. It redirects to unauthorized.
- Do not document Quick Add as the normal scan path.

Example: Check in from the phone footer after tapping a location.
