## Content requirements

Concepts:
- The feature is off until Expirations is on in Settings.
- The window defaults to 60 days.
- The list shows the first 100 rows. Counts can be larger.
- Replace or clone has five radios. What they do to stock is Uncertain.
- A past date warns and does not block save.

Prerequisites and permissions:
- SHOW_EXPIRATIONS. Read-only can view the list and cannot manage.

Customer actions:
1. Turn Expirations on. Set Expiring Soon if you want a window.
2. Open Expirations.
3. Click a row to edit that product’s date. Dates run from 2018-01-01 through 2050-01-01.
4. On the editable list, click manage, leave Replace and Delete or pick another radio, and save only if you accept that the stock effect is not documented here.

Options and settings: Radios: Replace and Delete, Replace only, Clone and Delete, Clone and Check-out, Clone only. Default is Replace and Delete.

Expected results: The list and the product date are confirmed. The replacement API’s stock result is not.

Errors and troubleshooting: “You must select an expiration date.” “This date has already passed!” “You must select a product number.” “That product number already exists!” Editor API errors may only appear in the browser console.

Limitations:
- A product expiring later today can be counted differently from how it is listed.
- Do not document each radio’s inventory effect.

Example: Filter to expired gloves and open the product to set a new date. Stop before replace-or-clone unless the stock effect has been verified live.
